## 抓包方法（可复现）

设备自身即 MQTT Broker（明文，19883 端口）。用任意 MQTT 客户端以 `Lambot`/`lambot123`
连接后订阅以下两个主题，即可旁路观测 App 与设备的全部通信：

- `device/{device_id}/robot` —— **下发方向**（App / HA → 设备）
- `device/{device_id}/app` —— **上报方向**（设备 → App / HA）

## 心跳与姿态流机制（v1.2 受控实验）

- 连接 Broker 后设备**不会**立即推送 f1 姿态流；需持续发送 **f41 心跳**（3~5s 间隔），
  实测首个 f1 在连接后约 13s、若干次心跳后才出现；
- 无心跳时仅有零星报文（f28/f29/f19 配置包、f16 间歇、f66 握手响应等）；
- 姿态流为**爆发式**上报：动作执行时密集（存在同秒连续多条），静止时稀疏，
  不能假设匀速采样，做定量分析应以动作前后稳定值为准。

## 回充标准时序（f25 下发后，v1.2 实测）

1. f25 下发 → 设备上报 `f2 {"an":3,"st":1}`、`f4 false`；
2. f16=5（回充对接中，实测持续约 20s）：期间多次原地旋转调整朝向、f7 小地图
   间歇更新、f22 上行与 f16 同值镜像；
3. 落座完成：`f2 null` + `f4 true` + `f16 1` 三连发，随后 f21 上行广播一次
   完整位姿（含 pitch/roll）。

## 清扫模式枚举（f78 下发 / f54、f32 上报）

| 值 | 含义 | 依据 |
|----|------|------|
| 0 | 沿边 | f78 p=0（用户点"沿边清扫"） |
| 1 | 待机/默认 | f32 device_mode=1（待机时页面刷新上报） |
| 2 | 弓形（＝＃字形，两种叫法同一之字形路径） | f78 p=2（round1 点"弓形"与 round2 点"＃字形"均发 p=2） |
| 3? | 疑存在于智能区域配置（f102 clean_mode=3），语义待验证 | f102 上报 |

> **注意**：此枚举与华为 103K Profile 的 mode（2 弓形/3 沿边/9 区域）**完全无关**，
> 不可混用。区域清扫不走 mode，走 **f68**。

## 与当前 HA 集成的差异（记录备查，本轮未改代码）

1. `vacuum.py` 的 `CMD_SET_MODE = 54` 下发**无效**——54 是上行方向的模式上报，
   正确下发指令为 **f78**；
2. 暂停建议跟随官方带参 `f24 p=1`（无参目前也能被接受）；
3. `_STATE_MAP` 的 `5: "paused"` 实测为"回充对接中"；7="returning" 是对的；
   建议补充 0（遥控待机）、9（遥控旋转）、14/15；
4. 可新增能力：方向遥控（f20 前进 / f21 后退已实测确认；f23 为单向约 45°
   旋转脉冲，左右转向可尝试 f20/f21 的 a 参数取 ±π/2 弧线转向——**此假说未
   验证**）、指定区域清扫（f68，数据源 f28/f29）、
   虚拟墙读写（f29 下行/f9 上行）、模式反馈（f54/f32/f2）、音量（f60）、
   预约定时展示（f27，注意疑似云端）；
5. 观测到"暂停清扫后设备直接转入回充（f16 p=7）"一次，是否为固定行为待验证。

## 待验证清单

- **f23 左/右转向的编码机制**：受控实验已证明无参 `{"f":23}` 三连单发均为同一
  方向（yaw 负向、约 45°），v1.1 记录的"同参数触发相反旋转"为旧误判；下一步
  可测 f23 带参形式（如 `p={"a":±π/2}` 或 `p=±1`），或验证"左右=f20/f21
  a=±π/2 弧线转向"假说；
- f22 上行语义最终确认：v1.2 实测 9/0/5 与 f16 状态同步，倾向"状态事件镜像"，
  需一次已知运行时长的场景排除"清扫时长秒数"旧解读；
- 定时清扫指令：f27 结构已知（e/s/enable），但本轮用户未成功新建定时（预约在
  设置页，疑似云端下发），需在定时生效或设置时再抓；
- f5 / f6 / f25(p) / f58 / f62 的具体语义；
- f2 中 ms / pt 字段的完整格式；
- f86 / f87 / f82 / f83 / f34 的响应内容；
- 暂停后自动转回充是否为固定行为。
